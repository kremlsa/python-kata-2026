Теория 1. Python — язык с динамической, но строгой типизацией
Тип принадлежит объекту, а переменная ссылается на объект.

value = 10
print(type(value))  # int
value = "10"
print(type(value))  # str



Python не выполняет произвольное неявное преобразование между строками и числами.
10 + "5"       # TypeError
10 + int("5")  # 15



Основные типы, которые понадобятся:
Тип	Пример	Особенность
int	42	Целое число
float	3.14	Число с плавающей точкой
str	"admin"	Неизменяемая строка
bool	True	Подтип int
NoneType	None	Отсутствие значения

Важный нюанс:
isinstance(True, int)  # True
True == 1              # True



Почему это важно для AppSec?

Представим, что API принимает числовой идентификатор пользователя. Проверка isinstance(user_id, int) неожиданно пропустит True.

Теория 2. Равенство и идентичность
В Python существуют два принципиально разных оператора:
- == — сравнение значений.
- is — проверка идентичности объектов.
a = [1, 2]
b = [1, 2]
print(a == b)  # True
print(a is b)  # False



Для проверки отсутствия значения используют:
if value is None:
    ...

А не value == None.


Теория 3. Truthiness
Любой объект Python может участвовать в логическом условии.
bool("")       # False
bool(0)        # False
bool([])       # False
bool(None)     # False
bool("False")  # True
bool("0")      # True



Рассмотрим потенциально опасный код:
def check_limit(limit):
    if not limit:
            return 100
    return limit



Здесь 0 и None обрабатываются одинаково, хотя семантически могут означать совершенно разные вещи.

В безопасности важно различать отсутствие параметра, некорректный параметр и допустимое нулевое значение.


Теория 4. Валидация на границе доверия

Предположим, приложение получает JSON:
{
  "user_id": 123,
  "role": "admin",
  "enabled": true
}


Данные поступают из недоверенного источника.

Валидация должна проверять не только наличие полей, но и:
1. Тип значения.
2. Допустимый диапазон.
3. Формат.
4. Семантические ограничения.
При этом валидация роли admin не означает, что пользователь действительно имеет административные полномочия. Валидация и авторизация — разные механизмы.

AppSec-выводы:
- Проверяй типы данных на границе доверия.
- Не используй truthiness там, где нужно различать конкретные значения.
- Валидация входных данных не заменяет авторизацию.
- Проверяй, откуда поступает информация о полномочиях.
- Используй положительные проверки допустимых значений, когда домен данных ограничен.
